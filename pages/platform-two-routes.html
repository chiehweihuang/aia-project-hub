00 / CONCLUSION

結論先行

預設建議

以路線 A（netiCRM 嵌合）作為主要平台，但把活動票券與捐款明確劃為 netiCRM 原生功能；路線 B 的價值在前台可控性與未來跨界擴充，不適合作為近期 ADALS 2026 售票的主架構。

這是參考建議，非定論，最終由 AIA 理事會決定；翻盤條件見下方第 4 區。

核心取捨是兩件事的對撞：一是 NGO 核心功能（活動報名、收款、捐款、CRM、電子報、會員、台灣合規）在單一系統內的原生整合度，二是前台 UI 完全掌控與未來跨界（付費課程、跨國收款）的彈性。路線 A 在第一件事上有結構性優勢：六大功能原生整合、台灣合規層（國稅局電子化上傳格式、ezpay 電子發票）內建、維運由廠商吸收、2 年總持有成本（TCO）區間窄而可預算。路線 B 在第二件事上有結構性優勢：前台在自家 WordPress 內、可逐項修補 a11y 並公開稽核成果、未來要做 LMS 或多幣別跨國收款時是「加外掛」而非「換系統」。但路線 B 的代價是整合縫多、跨系統對帳負擔重、台灣合規完全無現成外掛需自建、key-person 風險高，且 2 年 TCO 區間極寬（經第三輪重算後，中間配約 NT$115,000 至 175,000,高端配可達 NT$390,000 以上），難以做預算。

a11y（無障礙）與現金流如何權衡，是這次決策最微妙的地方，也是最需要對 AIA「以 a11y 為招牌」的定位誠實的地方。在 a11y 上，兩條路線達 WCAG 2.2 AA 在技術上都可能，但障礙性質不同：路線 A 的障礙是廠商意願（底層 CiviCRM 模板的已知缺陷 AIA 無法自行修補，需 netiCRM 配合），路線 B 的障礙是維運紀律與持續預算（每次外掛更新都可能引入回退，需每月人工螢幕閱讀器測試）。對一個招牌就是 a11y 的 NGO，「能公開宣稱自家報名流程已達 AA 並持續維護」這件事，路線 B 的可控性確實較高；但「實際達標且不退步」需要路線 B 投入路線 A 不需要的持續人力。近期（ADALS 2026,6 月底要能線上刷卡、150 至 200 人、多票種）現金流與時間壓力下，路線 A 的確定性勝出；a11y 招牌的長期可控性是路線 B 唯一能在這個面向上扳回的點，但它要用持續預算去換。

TCO 數字第三輪查核校正（2026-06-04）。路線 A：原列「WordPress 主機 2 年 NT$12,000」應移除（netiCRM 為 SaaS 已含主機），2 年 TCO 中位由 NT$78,000 下修為約 NT$56,000 至 76,000；微型方案 NT$12,960 是樂觀下限，ADALS 規模保守基準接近小型方案 NT$24,000。路線 B：原「中間配 NT$205,000 至 210,000」經重算實為偏高端，中間配約 NT$115,000 至 175,000。校正後 A 對 B 的量級差距仍在。

無障礙數字一律以實測為準。netiCRM 前台 a11y 經實測:三個真實客戶捐款表單 Lighthouse 無障礙 81-86(失分集中於色彩對比、缺 main 地標、下拉選單缺名稱等可修項)。報告中所有金流訂閱與外掛年費，凡經核查標記過時或無法核實者，已在內文降溫並標注「待確認」。

廠商回覆更新（小花 2026-05-29 來信）:多項待確認已由 netiCRM 業務窗口拍板,多數對 netiCRM 有利。

  • NPO 費率:netiCRM 代辦藍新進件,取得 NPO 優惠刷卡 2.2%、無年費、刷卡才收,解決長期費率爭議。
  • 雙語加購含活動報名/購票頁（反轉先前疑慮）:NT$10,500 同時涵蓋募款頁與活動報名/購票頁,海外可英文報名付費並收英文收據;先前「只含募款頁」的推測經 vendor 確認不成立。

  • 抵稅收據:資格前開一般收據、取得資格後開正式可抵稅收據,此設定無額外費用。
  • SLA 與時程:netiCRM 客服 1-2 工作天;藍新審核 5-10 工作天;30 天導入陪伴可建報名頁;早鳥 6/22 開賣。

a11y（P.S.,即 A3 預測的 showcase 開口）:小花坦承前台 WCAG AA 仍在推進、今年達標有挑戰,但主動請 AIA 提供台灣與國際對 a11y 的重視度與法規壓力觀察以排改善優先序。翻盤條件 3（廠商拒絕書面承諾）現為軟性開門、非拒絕(目前僅願意開對話、尚未承諾必改)。合作路徑很實在:AIA 本來就會測報名/付款頁,測後提具體修改建議、以「客戶」身分做成 case study;且 netiCRM 統一更新,一旦照建議改好,按本研究會直接讓 300 家以上(官網稱 500+)在用 netiCRM 的 NPO 一起受惠,不只自家達標。

01 / DEFINITIONS

兩路線定義

路線 A — netiCRM 嵌合

netiCRM 是 CiviCRM（2004 年起發展的開源 NPO 關係管理系統，採 AGPL 授權）的台灣中文化 fork，加上客服層 SaaS，由網絡行動科技（Yo Group / Netivism）營運。它在單一系統內原生處理活動報名（多票種、早鳥、優惠碼、QR 簽到）、捐款與定期定額、donor/member CRM、電子報、會員管理，並疊上台灣在地化合規層（國稅局捐贈扣除額電子化上傳格式、ezpay 電子發票串接、收據自動產出）。計價為微型方案 NT$12,960/年（3,000 聯絡人）加開通費 NT$8,000（簽 2 年約免）；金流走藍新或綠界 gateway，netiCRM 不另抽手續費。它以連結跳轉、自訂子域名（如 donate.aia.org.tw）、表單嵌入或 REST API 接進 AIA 的 WordPress 站，但不建議 iframe 嵌付款頁。底層是 Drupal 10 生態，與 AIA 的 WordPress + Elementor 主站異質，因此前台有跨域跳轉感。

路線 B — WordPress plugin 大軍 + SaaS 自組 CRM

在 AIA 既有的 WordPress + Elementor 主站上，以 WooCommerce 為金流與票券核心，疊加藍新 gateway plugin、活動票券/行事曆 plugin（如 The Events Calendar 系列或 Eventin）、表單 plugin（Gravity Forms）、電子報 plugin/SaaS、會員 plugin；CRM 改用 SaaS（Airtable / NocoDB / Baserow / Notion，含開源自託管選項），靠 Zapier 或 Make 把報名、捐款、會員資料匯入。台灣合規（抵稅收據、公益勸募、統編、電子發票）沒有現成 WP plugin，需自建或人工處理。優勢是前台完全掌控與未來可改性最大化，代價是整合縫、跨系統對帳、外掛更新維運與合規自補。

A6 擴充性與未來路徑 法人化解鎖抵稅、月捐規模擴大是線性升級。付費課程是另接的商業模組（與 NPO 公益帳務本就分開，不算選型因素）；真正受限的是跨國多幣別收款（TWD-only）。台灣本地深耕路徑平滑。 付費課程/creator economy、跨國多幣別是「加外掛」；但技術債與 a11y 回歸隨外掛數線性增長。跨界擴充佔優。

03 / RECOMMENDATION

建議與翻盤條件

預設建議：路線 A（netiCRM 嵌合）為主要平台。理由綜合六軸：功能原生整合度高（A1）、2 年 TCO 低且可預算（A2）、維運負擔結構性低且無 key-person SPOF（A4）、資料主權與台灣合規結構性佔優（A5）、台灣本地深耕的升級路徑平滑（A6）。a11y 重點軸（A3）上路線 A 的可控性較低，但維運成本也較低，且可透過把 ADALS 2026 作為與廠商共同的 WCAG AA showcase 來爭取改善。對一個成立 2 年、人力有限、近期有 ADALS 6 月底硬期限的組織，路線 A 在確定性、時間風險、現金流可預測性上的優勢，壓過路線 B 在前台可控性與跨界擴充上的優勢。

這是參考建議，非定論，最終由 AIA 理事會決定。以下逐條翻盤條件，任一成立就應重新評估改採路線 B（或路線 B 為主、netiCRM 為輔的混合）：

  1. AIA 在未來 12 個月內確定能取得穩定技術維運能量。若已有願簽長期維護協議（含 SLA）的固定外包商或全職/長駐技術志工工程師，路線 B 的最大風險（key-person SPOF、維運紀律）被緩解，前台可控性的優勢就能兌現。反之若無人持續維護，路線 B 不建議。
  2. a11y 招牌的「對外可宣稱自家達 AA」被理事會列為高於成本的首要戰略目標，且願意編列每月人工 a11y 測試的持續預算。若這對 AIA 的品牌不可妥協，而 netiCRM 又談不到明確改善承諾，路線 B 的前台完全可控就成為決定性因素。
  3. netiCRM 在合約談判中拒絕對 WCAG AA 改善（含報名頁、付款流程、接合縫文件）做出書面承諾。路線 A 的 a11y 上限若被鎖在修不動的底層模板，且 AIA 對外無法宣稱報名流程達 AA，對 a11y NGO 是策略性風險，此時路線 B 的可控性勝出。
  4. AIA 未來 3 年的優先路線圖明確包含東南亞跨國多幣別收款（以外幣標價並結算）。netiCRM 為 TWD-only，真正的跨國多幣別在路線 A 做不到（海外與會者仍可持外卡以台幣計價，只有「外幣標價＋外幣結算」才真的卡）。付費課程不在此列：它是協會的商業行為，本來就會放在專門的 LMS（與 netiCRM 或 WordPress 主站皆獨立），且在 NPO 帳務上與公益捐贈分開，不構成選型因素。若理事會確認跨國多幣別是核心方向（而非「以防萬一」），路線 B 的擴充彈性成為主導因素。此條須先驗證需求真實性，不要為未證實的未來需求現在就承擔路線 B 的整合複雜度。
  5. 3,000 聯絡人上限在 2 年內確定會被遠超，且小型/中型方案升級後 netiCRM 成本逼近路線 B 的中間配。若 donor + member + 歷年活動報名累積增長極快使方案需連續升級，路線 A 的成本優勢縮減，可重新比價。
  6. 藍新定期定額在 WooCommerce 出現成熟、定價透明、持續維護的原生解法，且 a11y 達標。路線 B 目前最大技術缺口若被市場填補，功能覆蓋缺口（A1）被補上，評估天平會移動。

04 / DEEP DIVE

逐軸詳述

每軸含路線 A 發現、路線 B 發現、對抗核查修正點、取捨判斷。預設收合，點標題展開。

A1 功能覆蓋完整度

路線 A 發現

六大功能在單一系統內原生整合：活動報名支援最多 10 個費用選項的多票種、早鳥、優惠碼、QR 簽到；捐款單筆與定期定額原生；donor/member CRM 整合度高；電子報原生但有發送速率限制；會員多類型分級原生。台灣合規層（國稅局捐贈扣除額電子化 CSV 匯出）內建。兩個真實缺口：一是定期定額捐款人無法自助修改金額/頻率/扣款日/暫停，需組織管理員後台代操；二是企業捐款統編的抵稅電子化僅適用個人綜所稅、企業/組織尚不適用。對現為「人民團體」的 AIA，後者暫不適用（認定後才開放抵稅）。

路線 B 發現

工具齊全但無單一原生解。活動票券候選有 Eventin、FooEvents、The Events Calendar 系列等，但都未同時宣告「藍新 + 繁中全本地化 + WCAG 2.2 AA」三者成立，需逐一測相容性。藍新定期定額是路線 B 最大技術缺口：官方免費 plugin 不含 recurring，需第三方商業 plugin（定價不透明）或改用 TapPay 繞開。台灣抵稅收據、公益勸募欄位無現成 plugin，需完全自建。

對抗核查修正點

（1） netiCRM ezpay 電子發票以「一次性」概括低估了後續使用費，實為 NT$16,800 含稅一次性實作費加 ezpay 系統設定費 NT$3,000,另有按量計費的後續使用費。（2） netiCRM 前台 a11y 以實測為準（真實客戶捐款表單 Lighthouse 無障礙 81-86）。（3） TapPay for WooCommerce 定價 NT$5,980 至 14,980 無法核實，核查時產品頁顯示「Coming Soon」，標「待確認」。（4） 藍新「非 WC Subscriptions 正式認證 gateway」屬推論，「需第三方商業 plugin」實際有多個市場解法，信心降為 medium。（5） Airtable NPO 折扣不適用年付方案，來源引用舊版方案結構，信心打折。（6） netiCRM 雙語募款頁 NT$10,500,5/29 小花來信確認同時涵蓋募款頁與活動報名/購票頁（不限數量、含英文確認信與收據），先前「只含募款頁」的推測經 vendor 確認不成立。

取捨判斷

路線 A 較優：六大功能原生整合、台灣合規內建，對人手有限的 NGO 是少整合縫、少維運。路線 B 的根本問題不是缺工具而是缺整合，每個整合縫都是後續資料一致性與維護的風險點。前台 UI 完全控制是路線 B 的真優勢，但在本軸不計分。

A2 2 年 TCO / 現金流

路線 A 發現

授權費 2 年 NT$25,920（簽 2 年免開通費）；一次性建置加購（雙語頁 NT$10,500、自訂域名首年 NT$6,000 加每年維護 NT$2,000、收據客製下限 NT$3,750）約 NT$24,000 至 42,000；維運工時 2 年約 NT$3,600 至 11,200（原列「WordPress 主機 2 年 NT$12,000」經第三輪查核移除：netiCRM 為 SaaS 已含主機）。不含電子發票串接的 2 年 TCO 經口徑校正後約 NT$56,000 至 76,000。其中雙語頁（海外與會者必要）屬必花、自訂域名與收據客製為選配；只做必花（授權加雙語加維運）約 NT$40,000 至 48,000，加選配後達上述上限。dev 工時近零，因 netiCRM 是全代管 SaaS。

路線 B 發現

場景矩陣原估省錢最低配 NT$149,910、中間配 NT$191,276、高端配 NT$390,500。最大變數是建置 dev 工時（原估 83 至 171 小時），「免費大軍」只有在 Make NGO 方案核准、NocoDB 自託管有人維護、dev 工時低於 80 小時三條件同時成立時才能壓低，任一失敗即推高至 NT$200,000 以上。

對抗核查修正點

路線 B 的 TCO 被系統性低估，核查後須上修：（1） WooCommerce Subscriptions 原引用 $199/年已過時，官方現為 $279/年。（2） The Events Calendar Essentials（$259/年）不含 QR check-in，該功能是 Pro 層（$399/年）才有。（3） 台灣 freelancer 時薪上限 NT$700 偏低，市場有經驗者實際 NT$800 至 2,000/h。（4） MailPoet Business 估 $15/月偏高，二手來源指向 $10 至 12/月，標「待確認」。綜合修正後，路線 B 省錢最低配真實 2 年 TCO 保守應在 NT$160,000 至 170,000 以上，中間配約 NT$205,000 至 210,000。路線 A 核心授權與加購均有官方定價頁支撐；唯電子發票串接費實為獨立固定費 NT$16,800（待確認 ezpay 後續使用費）。

取捨判斷

路線 A 有結構性成本優勢：dev 工時近零、加購透明、現金流可預測、上限清晰。路線 B 區間極寬（NT$160,000 至 390,000+），組織難做預算，且台灣合規的自建成本未計入，是其隱性劣勢。路線 A 主要的向上彈性風險是 3,000 聯絡人上限，超過需升小型方案（差額約 NT$11,040/年）。

路線 A 發現

a11y 問題集中兩層：一是底層 CiviCRM/netiCRM 模板已知缺陷（色彩對比、缺漏地標、select2 焦點、accordion 不一致、table-based 排版），托管版 AIA 幾乎無法自行修補；二是 WordPress 主站到 netiCRM 子域名的接合縫，焦點管理跨頁跳轉責任模糊。可控性低、依賴廠商。但 netiCRM 是公益 SaaS 廠商，若 AIA 以 ADALS 2026 報名/付款流程作為雙方共同的 WCAG AA showcase 提案，廠商有動機協助改善 — 這是最大上行空間，但是談判結果而非既有承諾。

路線 B 發現

主站完全在 AIA 手上，可逐項修補、修了算自家成果、可公開稽核。但「掌握」不等於「免費達標」：WooCommerce 10.0 在 accessibility-ready 主題下宣稱達 WCAG 2.2 AA，但此條件排除了 AIA 實際使用的 Elementor 情境；Elementor 官方僅宣稱 WCAG 2.0 AA；The Events Calendar 不宣稱完整合規；Paid Memberships Pro 僅部分符合 WCAG 2.1 AA；四個 CRM SaaS 的嵌入 widget 均不建議作為對外報名/捐款 AA 介面（Airtable 鍵盤操作測試失敗、Notion 多項違規）。藍新金流台灣 plugin 的 iframe 付款層無公開 a11y 文件，是最大已知黑洞。

對抗核查修正點

三個數字無一手來源、不可作對外或法律/採購論證：（1）「78% 電商無障礙訴訟指向結帳流程」僅出自一家販售 a11y 工具的商業公司部落格，有利益衝突，不可引用。（2）「自動化工具只能發現 30 至 40% 的 WCAG 問題」在其聲稱來源中查無實據，其他來源反指約 57%，此數字作廢。（3） Airtable 外部介面達 WCAG 2.2 是「2026 年初」的承諾，截至本報告未見官方確認已達成，應視為待驗。WooCommerce 10.0 達 AA 的主張本身成立，但條件（accessibility-ready 主題）排除 Elementor。

取捨判斷

兩條路線達 AA 技術上都可能、都需主動投入。可控性：路線 B 高於路線 A。維運成本：路線 A 較低（修補集中於單一廠商介面，廠商修好就全面生效；路線 B 每個外掛都是獨立回歸風險點，需每月測試）。若能與 netiCRM 談到明確 WCAG AA 改善承諾，路線 A 總維運成本更低、可控性比外表高；若廠商不配合，路線 A 的 a11y 上限被鎖在修不動的底層模板，且 AIA 對外無法宣稱自家報名流程達 AA。路線 B 的前台完全可改是真優勢，但轉成「已達 AA 並持續維護 AA」需要每月測試預算與人力。這個軸是路線 B 唯一在策略定位上能扳回的點，但代價是持續紀律與預算。

補強:自建的 a11y 測試負擔(為什麼「無法承諾」)

對「以 a11y 為招牌」的協會,自建最致命的不是成本,是無法承諾自家網站無障礙。即使排除「報名頁本身」,自建路線下每個元件都要各自做完整 a11y 測試加研究加 case study,且每月重測(外掛各自更新會 regress):

  • 互動元件:活動行事曆、表單(label / aria-live / focus)、全站導覽(漢堡選單 aria-expanded / Esc / focus)、站內搜尋、Elementor 的 accordion / tabs / modal / carousel(Elementor 僅宣稱 WCAG 2.0 AA)。
  • 交易周邊(不含報名頁):捐款頁導覽、金流 iframe(藍新 / 綠界,無公開 a11y 文件、已知黑洞)、WooCommerce 結帳 blocks(Elementor 主題下不在 AA 保證範圍)。
  • 內容層:PDF / 文件(tagged + HTML 替代 + 逐字稿)、影音(字幕 / 逐字稿)、表格(th scope)、全站圖片 alt 與標題層級與對比與縮放。

為什麼「無法承諾」:這是 N 個獨立廠商外掛、各自更新、各自會 regress,所以給不出「本站持續達 AA」的承諾,且要每月整串重測。不對稱聲譽風險(對 AIA 特有):別人做 80 分網站沒人罵,無障礙協會做 80 分是頭條級矛盾;協會標準被招牌綁死在「必須能承諾 AA」,而「外掛各自更新」在定義上就無法承諾。對照路線 A:一套系統去測,並把改善推給廠商當 showcase(廠商已開門,見頂部廠商回覆),範圍有界、可承諾。

A4 整合 / 維運 / 對帳 / key-person

路線 A 發現

維運複雜度低：基礎架構、安全 patch、版本升級全由廠商吸收（日台跨地理每日異地備份），AIA 組織端每年約 50 至 100 小時行政操作（非工程）。對帳在單一系統內完成。整合深度有天花板：純 SaaS 租用上限是「跳轉連結 + 表單嵌入」，REST API 無 webhook（需輪詢）、API 需額外付費且 IP 鎖定。若日後要深度整合（CRM 資料即時呈現在 WordPress），會遇技術牆，屆時需付費採購整合建置（NT$40 萬+）或轉系統。

路線 B 發現

前台體驗一致是優勢。但對無工程師組織，維運負擔被系統性低估：藍新 webhook 一旦失敗 WooCommerce 會自動停用、產生人工對帳缺口；Zapier 任一步驟失敗整個停止、OAuth 過期不主動通知；月底需比對藍新後台、WooCommerce 訂單、CRM 三份資料。最嚴重的是 key-person 風險：系統知識集中於建置者，台灣 NGO 常見「建完即走」的 SPOF，一旦負責人離開，修一個 webhook 斷線可能耗數週。

對抗核查修正點

路線 B 數字品質較低，多項須降溫：（1） netiCRM 客服 SLA：5/29 小花來信為 1-2 個工作天初次回應（先前官方頁未公開,已更新）。（2） netiCRM 採用組織數官網首頁現為「500+」、GitHub README 為「nearly 300」，以首頁為準。（3） Wordfence「單週最高 231 筆」無法核實；「Hash Key 60%」是單一服務商軼事估算。（4） 路線 B 年維運工時「110 至 245 小時」是研究者自行加總推算、非來源直接引用。（5） 外掛授權年費多項過時：Gravity Forms Pro 實為 $159、MemberPress 改名 Launch $399、Zapier 入門（Pro）約 $239.88/年（原報告 $828 誤植,該數其實是 Team 起價,此項是對抗核查層自己引入的錯,已於 6/04 雙模型查核更正）。

取捨判斷

路線 A 在維運負擔與對帳複雜度上結構性佔優，但整合深度有天花板。針對 ADALS 2026 的緊迫性（6 月底、約 3 週窗口）：路線 A 的活動報名是現成功能，設定即上線，風險在連結體驗而非功能；路線 B 需新建 WooCommerce 票券流程、藍新串接除錯（估 2 至 4 週）、Zapier 驗證,3 週內可靠運行風險明顯較高。若 AIA 未來 12 個月仍無全職技術人員，路線 A 更能確保組織持續運作。

A5 資料主權 / lock-in / 台灣合規

路線 A 發現

資料主權是最清晰的優勢：netiCRM 客戶資料落於台日境內，已取得 ISO 27001:2022,隱私政策承諾跨境變更 30 日前通知。台灣合規功能原生（國稅局電子化申報匯出、ezpay 電子發票串接、收據自動產出）。底層 CiviCRM 資料模型開放（標準 MySQL schema），技術 lock-in 中等，但台灣在地化層（收據格式、報表樣板）是私有、遷移需重建。合約 2 年加 30 天退出窗口，需 AIA 提前做定期備份 SOP。

路線 B 發現

Airtable 預設美國、無亞太（僅澳洲），遷移功能僅 Enterprise Scale；Notion 預設美國、亞太需 Enterprise。兩者對 ADALS 國際與會者 PII 形成跨境傳輸疑慮。Baserow（MIT 授權）/ NocoDB 自託管於台灣境內可達最強資料主權，但 NocoDB 自 v0.301.0 改為 Sustainable Use License（自用自架不受影響），維運責任由 AIA 承擔。台灣合規完全無現成外掛，需自建或人工。

對抗核查修正點

法規現狀有過度斷言傾向，須加註：（1） 台灣個資法 2025 修正的「72 小時雙重通報」截至 2026-06 仍屬草案/子法待訂，施行日由行政院另訂尚未宣佈，不應以現在式描述，標「草案/待施行」。（2） 罰鍰上限 NT$1,500 萬成立，但「可直接處罰毋須先限期改正」僅適用「違反通報義務」這一特定義務，其他違規仍有限期改正前置。（3）「台灣 GDPR 適足性認定申請中」措辭過度，台灣僅處整備與對話階段、無正式申請受理紀錄。其餘（資料存放地點、export 上限、ISO 認證、NocoDB 授權轉換）均有來源支撐、成立。

取捨判斷

路線 A 在資料主權與台灣合規上結構性佔優，但非全覆蓋（公益勸募年度申報格式是否有專屬匯出未確認、30 天退出窗口偏短）。路線 B 缺口面更多：主流 SaaS CRM 預設美國伺服器在強化監管環境下不是零風險；台灣合規完全無現成外掛、每項都是獨立維運負擔。對 AIA 當前規模，台灣合規的自建成本是路線 B 最沉的隱性成本。若組織技術力足夠且想要最大資料自主，Baserow 自託管 + 台灣境內 VPS 是路線 B 中資料主權最強的子選項，但維運責任需承接。

A6 擴充性與未來路徑

路線 A 發現

方案六層級（微型 3,000 人到大型 100,000 人，再到獨立主機無上限），按比例補差額升級、資料連續不需重簽或遷移。法人化解鎖抵稅是「參數解鎖」；月捐規模擴大是線性升級。結構性限制在跨國多幣別：netiCRM 為 TWD-only，英文頁加購 NT$10,500 可解鎖英文前台與英文確認信/收據（廠商 5/29 來信確認），但無外幣標價與外幣結算（海外與會者仍可持外卡以台幣計價）。付費課程/LMS 雖非 netiCRM 原生，但屬另接的商業模組、與 NPO 公益帳務本就分開，不視為路線 A 的缺口。國際 grant 報表（CiviGrant 繼承）未獲官方確認。

路線 B 發現

升級是「疊加」而非「層級跳躍」。付費課程/creator economy 是路線 B 最強情境：LearnDash、MemberPress、Tutor LMS、WooCommerce Subscriptions 生態成熟，netiCRM 在此是 hard stop。跨國/東南亞：WooCommerce 多幣別外掛、Stripe 國際金流、WPML/Polylang 多語皆可疊加，是「加外掛」不是「換系統」。但每新增外掛擴大攻擊面與 a11y 回歸風險。法人化後台灣抵稅收據仍需自建，是相對 A 最明確的劣勢。

對抗核查修正點

（1） WooCommerce Subscriptions $199 已過時、現為 $279。（2） WordPress 2025 新增漏洞 11,334 個、42% 年增率正確，但「96% 來自外掛和佈景主題」有誤,2025 全年實為 91% 來自外掛、9% 來自佈景主題。（3） Baserow/NocoDB「支援數十萬至百萬筆無硬上限」是行銷主張非獨立基準測試，且 NocoDB 在大資料集下有已記錄的穩定性問題，標「待確認」。

取捨判斷

路線 A 明顯領先：法人化解鎖抵稅（A 是參數解鎖、B 需工程補建）、月捐規模擴大（A 線性升級）。路線 B 明顯領先：付費課程（A 是 hard stop）、跨國多幣別（A 是 hard stop）。國際 grant 報表兩條都需額外投入。框架：若 AIA 未來 3 至 5 年優先情境是「台灣本地 NPO 深耕」，路線 A 升級更平滑、後悔成本更低；若優先包含付費課程或東南亞跨國，路線 B 雖整合複雜但不存在硬阻。ADALS 2026 立即需求兩條路線均可支持，不構成此軸分歧點。

  8. CiviGrant 模組（國際 grant 申請/問責報告）是否包含於 SaaS 版，還是需客製。
  9. 3,000 聯絡人上限的實際衝擊與升級時點：盤點 ADALS 累計報名者 + 歷年捐款人 + 會員 2 年內是否逼近上限。
向路線 B 相關開發者 / 服務商確認（6 項）
  1. 藍新定期定額商業 plugin（ucheng.io / wpbrewer.com / cloudwp.pro / RY Tools 等）的實際定價、維護頻率、與最新版 WooCommerce Subscriptions 的相容性；RY Tools 免費版是否支援多票種與定期捐款。TapPay for WooCommerce 定價待確認（核查時顯示 Coming Soon）。
  2. Eventin 等 event plugin 是否有完整 zh_TW 正式語系檔，實際 WCAG 2.2 AA 合規程度需手動 Lighthouse 測試。
  3. 是否有台灣在地、可簽含 SLA 維護合約的服務商（非個人志工），年費區間多少（這是路線 B 可行的前提條件）。
  4. 路線 B 法人化後在 WordPress 實作國稅局電子化上傳格式的市場報價。
  5. 完整 plugin 組合做一次 WCAG 2.2 AA 手動稽核的台灣本地 a11y 顧問報價。
  6. MailPoet Business 在 1,000 至 3,000 訂閱者的確切定價。
向主管機關確認 + 內部盤點（6 項）
  1. 政府 2025 年底通過了新版個資法，但還沒公布哪天開始實施。要查清楚實施日，因為那天起 AIA 收會員和報名者個資的規定會變嚴。
  2. 外國捐款人沒有台灣身分證字號，收據上能不能用護照號碼代替？要問國稅局，這影響海外捐款怎麼開收據（目前兩條路線都得人工處理）。
  3. 如果走自組路線、要用 Make.com 這個自動化工具串資料，它的非營利免費方案台灣人民團體申不申請得到？申不到這條就要多花錢。
  4. AIA 有沒有固定的技術外包或長期技術志工，而且願意簽長期維護合約？有的話自組路線才可行，沒有的話自組風險太大（這是自組路線能不能成立的前提）。
  5. AIA 的捐款人大多是個人還是公司？如果多是個人，自組路線要處理的抵稅收據麻煩會比想像中小。
  6. AIA 未來 3 年確定要做付費課程，或要跨國（東南亞）收款嗎？如果是核心方向，平台選擇會不一樣；如果只是「以防萬一」，先別為它增加複雜度。

07 / CONTEXT

脈絡補充

  • 這份不是孤立決策，是先前一輪研究的延續。先前一輪的三路線成本（TCO）比較研究（整理在本專案的金流基礎建設決策頁）已得出「以 netiCRM 打包為預設首選」。本報告把問題收窄成「netiCRM 嵌合 vs WordPress 外掛大軍 + SaaS 自組」並補上無障礙與擴充性兩軸後，結論一致，兩次獨立分析都指向同一個答案：netiCRM。
  • A3 的「netiCRM 配合改善 a11y」不是空想，是已成形的合作構想。「把 ADALS 報名/付款流當成 netiCRM 的 WCAG AA showcase 一起做」是與 netiCRM 業務往來中形成的方向：既補 netiCRM 的 a11y 短板，又坐實 AIA 的權威定位。翻盤條件 3（廠商拒絕書面承諾）要在實際諮詢時當面問清。
  • 抵稅收據現在還用不到，先別拿它來比。AIA 現在的法律身分是「人民團體」，還沒取得可以開立「抵稅收據」（讓捐款人報稅扣抵的正式收據）的資格，所以兩條路線現在都還不能開，要等取得資格後才有差別。9 月 ADALS 賣票，現在真正要的只有三件：能不能線上刷卡、報名流程好不好用、無障礙做得好不好。抵稅收據這種「拿到資格才用得到」的功能現在還用不到，別把它當成「現在馬上要」的功能來比、來選。
