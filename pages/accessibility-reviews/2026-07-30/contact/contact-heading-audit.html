AIA 聯繫頁 Heading 結構檢查與修改對照

日期：2026-07-31
範圍：AIA 聯繫頁 live rendered DOM
目的：逐項說明目前 2 個 heading，提供可直接在 WordPress／Kadence 執行的修改對照。

先說結論

目前：H1 × 0、H2 × 2，共 2 個 heading。

建議完成後：H1 × 1、H2 × 1，共 2 個 heading。

  • 將「聯繫我們」從 H2 改成全頁唯一 H1。
  • 「社群媒體 SOCIALS」保留 H2，作為獨立頁尾區段。
  • 名字、Email、訊息類別、主題與訊息是表單欄位標籤，不需要改成 heading。
  • 修改的是 HTML Tag；「聯繫我們」仍可保留在表單左側，字級、顏色與版面不必移動。

判斷 Heading 的原則

  • 頁面主題使用 H1；這一頁的主題是「聯繫我們」。
  • 與主要內容並列的獨立區段使用 H2；頁尾「社群媒體」屬於這一層。
  • 表單欄位名稱維持 label，操作維持 button；不要只因文字醒目就改成 heading。
  • HTML 層級與視覺大小分開設定；改成 H1 不代表必須放大或移動「聯繫我們」。

為什麼這項修正重要

目前 heading 清單從 H2 開始，沒有代表本頁主題的 H1。使用螢幕閱讀器開啟 heading 清單時，會聽到「聯繫我們，層級二」和「社群媒體 SOCIALS，層級二」，但沒有一個最高層標題清楚表示這是一個聯繫頁。

這不代表表單內容完全讀不出來；表單欄位仍有各自的 label。問題在於頁面大綱缺少主題起點，使用者較難從標題導覽快速確認目前頁面與兩個主要區段的關係。

缺少 H1 本身不是所有頁面都能自動判定為 WCAG 違規；這一頁需要修正，是因為畫面上已經有明確的頁面主標題「聯繫我們」，但 HTML 把它和頁尾區段標成同一層。改成 H1 能讓語意與現有畫面一致。

測試界線：這是根據 rendered HTML 與 accessibility tree 所做的結構檢查，沒有執行 NVDA、JAWS 或 VoiceOver 的完整表單操作走查。修正後仍需在 staging 以 heading list 複查順序，再測試欄位、錯誤訊息與送出結果。

哪些文字不需要變成 heading

畫面文字正確角色原因
名字、Email、訊息類別、主題、訊息表單 label它們命名各自的輸入欄位，不是頁面章節。
發送按鈕它是送出表單的操作，不是內容標題。
Facebook、X、Instagram有目的網址時為連結它們是社群平台入口，不是「社群媒體」底下的內容章節。

WordPress／Kadence 實作步驟

  1. 進入「頁面 → 全部頁面 → 聯繫 → 編輯」。
  2. 打開左上角「清單檢視」，選取顯示「聯繫我們」的 Heading／Kadence Advanced Heading。
  3. 若是 Kadence Advanced Heading，在右側區塊設定找到 HTML Tag／Heading Tag，將 H2 改為 H1。
  4. 若是 WordPress 核心 Heading block，從區塊工具列將層級改為 H1。
  5. 不要移動區塊；若 tag 改變後預設字級跟著變化，以原本的 typography 設定恢復原字級。
  6. 「社群媒體 SOCIALS」維持 H2。
  7. 儲存草稿後先預覽，再檢查畫面與 heading list。

複查清單

  • DOM 中 H1 正好 1 個，文字為「聯繫我們」。
  • H2 正好 1 個，文字為「社群媒體 SOCIALS」。
  • heading 順序為 H1 → H2，沒有從 H2 開始。
  • 「聯繫我們」在 DOM 閱讀順序中位於表單之前。
  • 五個表單欄位名稱仍是已關聯的 label，不出現在 heading 清單。
  • 更改 tag 後，桌面與手機的字級、顏色、位置、間距和原設計一致。
  • 在 staging 以瀏覽器 Accessibility Tree 或螢幕閱讀器 heading list 複查完整順序。

對應標準：WCAG 2.2 1.3.1 Info and Relationships、2.4.6 Headings and Labels。這份文件只處理 heading 語意；表單欄位型別、focus 樣式、錯誤訊息與社群網址仍以聯繫頁完整檢查為準。
