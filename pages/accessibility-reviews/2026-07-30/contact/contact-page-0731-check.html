AIA WEBSITE REVIEW · 2026-07-31

聯繫頁無障礙與響應式版面檢查

給設計與 WordPress 製作人員的修正說明。首頁、ADALS 活動頁與聯繫頁分開記錄；本頁只談聯繫頁。

先看結論

聯繫頁有 2 項 P0：「主題」被設定成 Email 欄位，可能阻擋一般表單內容送出；頁面沒有 H1，螢幕閱讀器的標題導覽也缺少代表本頁主題的最高層標題。兩項都列為上線前修正。

版面本身在七種寬度都沒有水平捲軸，320px 表單已改成單欄，768px 以上的欄位寬度也足夠。其餘調整集中在鍵盤 focus、文字對比、頁面語言與社群連結。

測試範圍：本次檢查了 HTML、accessibility tree 與 Tab 鍵盤操作，沒有執行 NVDA、JAWS 或 VoiceOver 實機走查。缺少 H1 代表標題導覽目前不能判定為通過；修正 heading 後，仍需重新進行完整的螢幕閱讀器操作測試。表單標籤關聯等程式結構檢查則另外記錄，不等同於已完成螢幕閱讀器測試。

修正項目

P0 · 表單欄位

將「主題」從 Email Field 改成 Text Field

目前「主題*」的實際 HTML 是 <input type="email">。這不是顯示文字問題，而是欄位型別錯誤；輸入一般主題可能無法送出。

WordPress：編輯聯繫頁，選取 Kadence Advanced Form 裡的「主題」欄位，將欄位型別改為 Text Field。若目前區塊不能直接切換型別，就刪除這個 Email Field，在同一位置新增 Text Field，標籤仍用「主題」，並設為必填。

同一輪替「名字」加入 autocomplete="name"，「Email」加入 autocomplete="email"；若目前 Kadence 欄位面板沒有這個設定，先完成欄位型別修正，再於 staging 確認可用的擴充屬性方式。

完成標準：「活動合作詢問」可以通過瀏覽器欄位驗證；空白主題仍會顯示必填提示；名字與 Email 可由瀏覽器或輔助技術辨識輸入目的。

P0 · 頁面結構

將「聯繫我們」改為 H1，頁面標示為繁體中文

目前全頁只有兩個 H2：「聯繫我們」與「社群媒體 SOCIALS」，沒有 H1。螢幕閱讀器使用者開啟標題清單時，看不到代表本頁主題的最高層標題。頁面根節點是 lang="en-US"，但這一頁主要可見內容是繁體中文。

WordPress：將「聯繫我們」的 Heading Level 從 H2 改為 H1；視覺位置仍可保留在表單左側，不必移動版面。「社群媒體 SOCIALS」保留 H2。到「設定 → 一般 → 網站語言」確認為繁體中文，使輸出為 zh-TW 或 zh-Hant。完整英文段落才另外標示 lang="en"。

完成標準：頁面只有一個 H1「聯繫我們」；它在 DOM 閱讀順序中位於表單之前；後續主要區段為 H2；HTML 根節點反映頁面主要顯示語言。

開啟聯繫頁 Heading 逐項檢查與修改對照

P1 · 鍵盤 focus

讓目前正在填寫的欄位清楚可見

按 Tab 進入名字、Email、訊息類別、主題與訊息欄位時，computed style 顯示 outline: none 0px。送出按鈕已有可見輪廓，但五個輸入欄位只有原本的陰影，難以判斷鍵盤目前停在哪裡。

WordPress：在 Kadence 表單區塊的 Input Fields 設定中調整 Focus Colors，讓 focus 狀態有明顯邊框。若內建設定不足，可在 staging 加入：

.kb-advanced-form input:focus-visible,
.kb-advanced-form select:focus-visible,
.kb-advanced-form textarea:focus-visible {
  outline: 3px solid #ffbf47;
  outline-offset: 3px;
}

完成標準：只用 Tab 與 Shift+Tab 走過表單時，每一步都能立即看出目前欄位；輪廓不被卡片或欄位邊界截掉。

P1 · 文字對比

加深送出按鈕、必填星號與桌面導覽文字

本次量測有三組一般文字未達 4.5:1：

  • 送出按鈕白字／橘底：約 3.55:1。
  • 紅色必填星號／深藍底：約 2.08:1。
  • 桌面導覽灰字／黃色底：約 4.16:1。

可保留原本色系：送出按鈕橘底加深到接近 #b83b22；必填星號改為淺紅 #ffb4ab；黃色導覽上的文字改成較深的藍灰或深藍。

完成標準：一般文字與背景至少 4.5:1；重新跑 Lighthouse desktop／mobile，不再出現 Color contrast 失敗。

P1 · 社群連結

Facebook 補正確網址；X 與 Instagram 先不顯示

三個圖示目前都是空的 href。鍵盤可以停在上面，但啟用後只會重新載入目前頁面，使用者無法到達社群帳號。

WordPress：Facebook 設為 https://www.facebook.com/apacaia/。X 與 Instagram 帳號尚未建立，先隱藏圖示與連結；帳號建立並確認網址後再顯示。

完成標準：Facebook 可用 Tab 聚焦並開啟正確頁面；頁面上沒有空網址或尚不存在的社群入口。

響應式畫面

套用 WCAG 文字間距測試值後，320／768／1024／1280／1440／1742／1920px 仍沒有水平捲軸。聯繫頁目前不需要另外調整欄數；修正重點是表單可用性與語意。

程式結構與版面檢查已通過

HTML 表單標籤已正確關聯

名字、Email、訊息類別、主題、訊息五個欄位都有可見 label，且與實際控制項關聯。這是 DOM 結構檢查結果，不代表已完成 NVDA 操作測試。

必填狀態已使用原生屬性

五個欄位都有 required，不是只靠紅色星號表示。

欄位控制項使用原生 HTML

文字框、Email、select、textarea 與 submit button 都可由鍵盤到達。

七種寬度沒有水平捲軸

一般狀態與文字間距測試後均為 scrollWidth = clientWidth。

Skip link 與主要區域存在

Skip link 可跳到主要內容；320px 測試時，目標沒有被固定頁首遮住。

圖片替代文字配置合理

頁首標誌有可辨識名稱；頁尾裝飾性短標誌使用空 alt。

網站開發與 staging 複查

背景圖網址改為 HTTPS

瀏覽器記錄到一個 mixed-content 警告：頁面以 HTTPS 開啟，但背景圖來源仍寫成 http://。目前 Chrome 會自動升級成 HTTPS，所以畫面仍能顯示；建議在媒體或區塊背景設定中直接改成 HTTPS。這是網站維護項目，不列為本頁的無障礙失敗。

在 staging 實際送出表單

本次沒有送出表單，避免從正式站寄出測試訊息。因此修正後需要在 staging 完成：

  1. 用一般文字主題成功送出。
  2. 缺少必填欄位時，用鍵盤確認焦點位置，再用 NVDA 確認錯誤訊息是否與對應欄位一起被讀出。
  3. 用 NVDA 確認送出後的成功訊息是否會自動宣告。
  4. 確認通知信實際送達指定信箱，且不會把表單內容暴露在網址或錯誤畫面。

欄位型別與 Focus Colors 的編輯位置可對照 Kadence Form (Adv) Block 官方說明。
