ADALS EVENT PAGE REVIEW · 2026-07-30

活動頁無障礙與響應式版面檢查

給設計與 WordPress 製作人員的修正說明。首頁與 ADALS 活動頁分開記錄；本頁只談 ADALS 活動頁。

先看上線範圍

Accupass 網址尚未提供：這是已知狀態；真正的報名連結要等網址確定後才能完成。但公開上線前，仍需先把目前無法操作的「立即報名｜Register」改成一般提示文字「報名即將開放｜Registration coming soon」，避免看起來像已經可以報名。

1 + 1P0：1 組必要條件；RWD：1 組共同決策
3 + 5P1：優先改善 3 項；上線後第一輪 5 項

P0｜本次上線必要條件

這一段只保留真正會阻擋公開上線的問題：錯誤內容與無效操作。嚴重 RWD 另列為上線決策項目；若尚未修完仍要先上線，需要相關人員在 LINE 明確確認。

RWD 是基本網站品質：手機、平板與桌面都應能正常瀏覽。只有當版面造成內容截斷、難以閱讀的窄欄、操作元件重疊或水平捲動時，才會同時形成無障礙問題。

螢幕閱讀器測試範圍：本次沒有執行 NVDA、JAWS 或 VoiceOver 實機走查。下方提到的影響，是根據 HTML heading 結構與 accessibility tree 判斷。目前 heading 層級有問題，因此標題導覽不能判定為通過；修正後仍需重新進行完整螢幕閱讀器走查。其他 DOM、鍵盤與版面檢查是各自獨立的結果。

P0 · 內容與操作

先修正會讓使用者看到錯誤內容或點到空連結的地方

位置：活動時程、四個報名 CTA、Makoto Ueki 講者卡與頁尾社群。

  • 時程：閉幕為 16:30–16:45，交流茶會卻從 16:40 開始。確認正確時間後，中文與英文時程一起修正。
  • 報名 CTA：Accupass 網址尚未提供時，改成一般提示文字「報名即將開放｜Registration coming soon」，不要維持按鈕外觀。取得網址後，再改成可用 Tab 聚焦、Enter 開啟的連結。
  • Makoto Ueki：將「Text link →」改成「LinkedIn →」，連到 正確的 LinkedIn。
  • 頁尾社群：Facebook 使用 正式網址。X、Instagram 帳號目前尚未建立，上線前若仍沒有有效網址，請不要顯示圖示、文字或空連結。開發時設定為只有提供有效網址才輸出對應的 <a> 連結；帳號建立並確認網址後再顯示。

完成標準：時程不再重疊；未取得 Accupass 網址時只顯示「報名即將開放」文字；頁面沒有 #、空白網址或「Text link」；Facebook 與 Makoto Ueki 的連結名稱和目的地正確；Tab 不會停在尚未啟用的報名、X 或 Instagram 元件上。

上線決策項目｜手機與平板 RWD

建議先修正再上線。若因活動時程仍決定先行上線，本報告不單方面阻擋，但需由相關決策人員在 LINE 明確確認知悉並接受目前風險，同時指定修正負責人與預計完成日期。

可直接貼到 LINE：「目前活動頁在 320px、768px 與 1024px 仍有講者、時程及票券文字欄過窄的 RWD 問題，建議修正後再上線。若考量活動宣傳時程仍決定先行上線，請相關人員明確回覆是否同意接受目前狀態，並一併確認 RWD 修正負責人與預計完成日期。」

需共同確認 · RWD

讓手機和平板不要繼續使用桌面版的多欄排列

先使用 Row Layout 內建的裝置欄數設定，分別調整電腦、平板與手機版。

目前最大的問題很單純：平板仍同時並排三位講者和四張票券；手機時程仍分成左右兩欄。每一欄因此只剩很窄的空間，文字不斷換行。

先看圖理解修改前後的差別 開啟講者與票券的各尺寸畫面比較 → 內含 320、768、1024、1280、1440、1742、1920px 的原始畫面、修改後畫面與實際文字寬度。

設定位置：在 WordPress 編輯器的清單檢視中選取對應的 Row Layout，再到右側「區塊 → Layout／版面配置」，利用電腦、平板、手機圖示設定各裝置欄數。三種裝置共用同一個 Row Layout，不需要複製三套內容。

講者區包住三張講者卡的 Row Layout：電腦 3 欄；平板 2 欄，目前呈現 2+1；手機 1 欄。
時程區每筆時程的 Row Layout：電腦 2 欄；平板 1 欄；手機 1 欄。所有時段使用相同設定。
票券區包住四種票券的 Row Layout：電腦 4 欄；平板 2 欄；手機 1 欄。

staging 查看建議：儲存後，可在 320px、768px 與 1024px 看看實際效果。平板主要觀察欄數；320px 則可一起留意外層 Row Layout 與文字卡內層的左右留白。目前兩層各約 48px，使文字欄只剩約 128px。比較頁的預覽先以兩層各 24px 作為測試值，實測文字欄約 221px；若只調整其中一層，改善幅度可能較有限。

若需要確認圖示與設定位置，可參考 Kadence Row Layout 說明。

完成標準：講者、時程與票券已照上方三組欄數設定；320px 的講者文字欄由約 128px 增加至約 221px；staging 的 320、768、1024、1280、1440、1742、1920px 沒有水平捲動，文字不再逐字或每兩三個字換行。若未完成即先上線，LINE 已留下共同決策、負責人與完成期限。

P1｜優先改善；未完成不阻擋本次上線

P1 · 頁面 title

讓瀏覽器頁籤清楚顯示活動名稱

位置：目前瀏覽器頁籤只顯示「論壇活動」。

改成「ADALS 2026 亞太資訊無障礙與數位共融領導力論壇｜APAC AIA」，讓使用者在多個頁籤、書籤與搜尋結果中能辨識本頁。

完成標準：瀏覽器頁籤顯示完整、可辨識且與頁面內容一致的活動名稱。

P1 · 頁面語言

將這個頁面的主要語言設定為臺灣繁體中文

位置：html lang="en-US"、英文 bio、英文票券說明與完整英文段落。

目前網站導覽與這個活動頁的主要內容都以臺灣繁體中文呈現，因此將頁面最外層的 <html> 標籤設定為 lang="zh-TW"。活動現場使用英文，不會改變這個網頁目前的主要語言；完整英文 bio、英文票券說明與其他英文長段落再個別使用 lang="en"。

WordPress 設定位置：這不是 Kadence 區塊設定。前往「設定 → 一般 → 網站語言」，選擇「繁體中文」；Kadence 會沿用 WordPress 的網站語言。儲存後再檢查網頁原始碼是否輸出 <html lang="zh-TW">。若未來建立獨立英文頁，建議使用多語系工具管理各頁語言，不要為了單一頁面改動整個網站的主要語言。

完成標準：檢查網頁原始碼最外層的 <html> 標籤，顯示 lang="zh-TW"；完整英文段落顯示 lang="en"。使用支援中英文的 NVDA 語音測試時，中文可正常朗讀，進入英文段落時切換英文語音。

P1 · 文字對比

把白底灰字與金色導覽列文字調深

位置：白底上的 #718096 灰字、金色導覽列上的兩個連結。

16 個白底灰字位置量測為 4.02:1；「論壇活動 Event」與「聯繫 Contact」為 4.16:1。一般文字需達 4.5:1。

  • 白底灰字改成更深的顏色，再實測確認。
  • 金色導覽列可先改用品牌深海藍 #003B5C，再量測。
  • 不要靠放大字級繞過一般文字的 4.5:1 要求。

完成標準：正文、導覽、按鈕各狀態皆 ≥ 4.5:1；大字才可使用 3:1 門檻。

P1｜上線後第一輪

第一輪 · Heading

補上唯一 H1，再把區塊與卡片標題分層

位置：頁首、講者、活動時程表、售票方案與頁尾。

目前：H1 × 0；24 個 H2 把區塊、講者姓名與時程項目混在同一層；英文標語與票種使用 H3；「包含／Includes」使用 H4。

  • 唯一 H1：活動正式名稱。
  • H2：關於／講者／時程／票券／社群媒體。
  • H3：講者姓名／每筆時程／票種名稱。
  • 一般文字：英文標語／包含／Includes／頁尾重複標題。

只改 Kadence Advanced Heading 的 HTML Tag，字級、顏色、間距與版面都可以保持不變。開啟 38 個 heading 的逐項對照。

完成標準：DOM 中正好一個 H1；主要區塊使用 H2；區塊內的講者、時程與票種使用 H3；標題不跳級。修正後重新進行 Heading 導覽與螢幕閱讀器測試；修正前不能把標題導覽判定為通過。

視覺整理

價格、按鈕、講者連結與卡片底部對齊

這是版面一致性，不直接列為 WCAG 問題。等上線前 5 組完成後，再用內層卡片 height:100%／flex:1，並以 margin-top:auto 將按鈕或連結推到底部。

完成標準：同一排卡片的價格、主要操作與底部邊界在同一水平線；每個價格仍清楚對應正確票種。

操作便利性

增加講者連結的垂直點擊範圍

三個講者連結量測約 80×22px／83×22px：寬度已超過 24px，只有高度少 2px，因此未直接達到 24×24px 的尺寸條件。不過，WCAG 2.5.8 允許尺寸較小、周圍間距足夠的連結；不能只憑 22px 高度判定不符合。本項改列為操作便利性建議。

建議做法：增加少量上下 padding，讓可點高度至少 24px；若希望手機操作更容易，可朝 44px 高調整，不需要放大文字。

操作辨識

讓三個英文 bio 展開按鈕可被清楚區分

這不是中文切換成英文造成的問題。三個 summary 展開按鈕目前都叫「READ ENGLISH BIO」；逐一使用 Tab 瀏覽時，螢幕閱讀器不一定會同時重讀前面的講者姓名，因此使用者可能無法立即確認現在要展開哪一位講者的介紹。展開功能本身正常，所以本項不單獨阻擋上線。

建議做法：讓每個按鈕的無障礙名稱包含講者姓名，例如「Read Frances West’s English bio」。畫面可保留「READ ENGLISH BIO」，姓名使用 visually-hidden 文字；若按鈕已透過 aria-describedby 明確連到講者姓名，則不必再加入隱藏文字。兩種方式擇一即可。

內容庫整理

圖片與背景圖網址統一使用 HTTPS

瀏覽器目前會自動把圖片網址升級為 HTTPS，所以這不是本次上線阻擋項目。上線後再整理媒體庫與背景圖網址，避免搬站或安全政策改變時載入失敗。

目前已符合的項目

Skip link 可用

可跳到主要內容，目標存在。

鍵盤焦點可見

抽查的互動元件有可見 focus indicator。

手機選單可鍵盤操作

Open／Close menu 有名稱與展開狀態。

英文 bio 可鍵盤展開

details/summary 的開合功能正常；只需改善名稱。

各測試寬度皆無水平捲軸

7 種寬度皆通過；文字欄寬度另依第 1 項調整。

主要 landmarks 存在

有 main、navigation、footer；頁面沒有表單或影音項目需要測。

無障礙複查清單

  1. 活動名稱是全頁唯一 H1；section／card 層級符合標題圖。
  2. 320／768／1024／1280／1440／1742／1920px 無 overflow，也沒有低於可讀下限的內文欄。
  3. 正文與互動文字對比 ≥ 4.5:1；焦點與元件邊界 ≥ 3:1。
  4. 互動目標達到 24×24px；若尺寸較小，需確認符合 WCAG 2.5.8 的間距例外。
  5. 頁面的主要語言為 zh-TW，完整英文段落標示 lang="en"。
  6. 所有保留的連結皆有正確目的地。

測試範圍與證據

本次以 live rendered DOM 為準，合併自動檢查、computed style／target size 量測、鍵盤走查與人工判讀。Lighthouse accessibility 為 92；這只表示頁面在本次 Google Lighthouse 自動檢查涵蓋的規則中得到相應分數，不代表網站已符合 WCAG，也不代表沒有其他無障礙問題。自動工具不會判斷 39px 文字欄的閱讀感受，也無法完整判斷 Heading 是否合理、替代文字是否正確或實際操作是否順暢。
