首頁無障礙與響應式版面檢查

給設計與 WordPress 製作人員的修正說明。首頁與 ADALS 活動頁分開記錄；本頁只談首頁。

先看結論

首頁有 2 組 P0，屬於本次上線必要條件：看起來可操作但實際無法使用的入口，以及頁尾空白社群連結。嚴重 RWD 另外列為上線決策項目：原則上應先修正；若仍決定先上線，需要由相關人員在 LINE 明確確認接受目前風險，並留下修正負責人與期限。

首頁會用來展示協會資訊、宣傳活動並承接購票入口，因此目前確認的 RWD 修正應先放到 staging 驗證；確認不同寬度沒有斷版後，再與本次上線內容一起套到正式站。這次只做 live 網頁的只讀檢查，沒有修改正式網站或 staging。

Lighthouse 分數不代表網站已經無障礙：90／94 只表示頁面在本次 Google Lighthouse 自動檢查涵蓋的規則中得到相應分數，不代表已符合 WCAG，也不代表沒有其他問題。完整判斷仍需合併人工檢查、鍵盤操作、各種裝置寬度與後續螢幕閱讀器測試。

P0｜本次上線必要條件

螢幕閱讀器測試範圍：本次沒有執行 NVDA、JAWS 或 VoiceOver 實機走查。下方提到的影響，是根據 HTML heading 結構與 accessibility tree 判斷，不是已完成的語音操作測試。目前 heading 層級不完整，因此標題導覽不能判定為通過；修正後仍需重新進行完整螢幕閱讀器走查。

P0 · 鍵盤操作

將「了解志工機會」連到聯繫頁

它由 div 與 span 組成，沒有 href，也不是 button，所以按 Tab 不會停在這裡，滑鼠點擊也沒有可靠的連結目的地。

處理方式：改成真正的連結並前往現有的「聯繫」頁，例如 <a href="/聯繫/">了解志工機會</a>。聯繫表單的「訊息類別」可加入「志工參與／Volunteer」，讓使用者到達後知道應選擇哪個項目。

完成標準：「了解志工機會」可用 Tab 聚焦，按 Enter 後前往聯繫頁；聯繫表單提供「志工參與／Volunteer」選項。

P0 · 空白社群連結

只顯示已有正確網址的社群入口

Facebook、X、Instagram 目前都有空的 href，鍵盤可以停在上面，但啟用後不會到達正確社群頁面。

WordPress：Facebook 改為 https://www.facebook.com/apacaia/；X 與 Instagram 尚未建立，先隱藏連結與圖示，建立並確認網址後再顯示。

完成標準：頁面沒有空白網址；所有仍顯示的社群入口都能到達正確頁面。

上線決策項目｜手機與平板 RWD

需共同確認 · RWD

手機與平板的核心文字目前過窄

320px 時，「關於我們」正文只剩約 85–105px。768px 時，「三大價值」正文約 107px。這些是核心介紹內容，已經被壓成難以正常閱讀的窄欄。

建議先修正再上線。若因活動時程仍決定先行上線，本報告不單方面阻擋，但需由相關決策人員在 LINE 明確確認知悉並接受目前風險，同時指定修正負責人與預計完成日期。

可直接貼到 LINE：「目前首頁在 320px 與 768px 仍有核心文字欄過窄的 RWD 問題，建議修正後再上線。若考量活動時程仍決定先行上線，請相關人員明確回覆是否同意接受目前狀態，並一併確認 RWD 修正負責人與預計完成日期。」

完成標準：320px 的主要正文至少約 220px 寬；768px 不再出現約 107px 的三欄正文；320／768／1024px 沒有內容截斷或水平捲動。若未完成即先上線，LINE 已留下共同決策、負責人與完成期限。

上線決策項目補充｜平板三欄卡片

需共同確認 · RWD 畫面與設定

三大價值與其他三欄卡片在 768px 太窄

768px 時「三大價值」仍排三欄，每張卡約 216px，正文實際只剩約 107px；「我們創造什麼連結」也維持三欄。建議這些卡片的外層加入共同 class，例如 home-card-grid，讓欄數依可用寬度自動減少。

.home-card-grid > .kt-row-column-wrap {
  grid-template-columns:
    repeat(auto-fit, minmax(min(100%, 20rem), 1fr)) !important;
}

完成標準：768px 不再出現每行只有少數中文字的窄欄；320／768／1024px 的卡片依空間改成一欄或兩欄。

P1｜優先改善；未完成不阻擋本次上線

P1 · 頁面名稱

補上瀏覽器與螢幕閱讀器會讀到的頁面標題

目前 <title> 是空的。分頁標籤、書籤和螢幕閱讀器的頁面清單都無法辨識這是哪一頁。

WordPress：補上首頁 SEO title，例如「亞太包容創新協會｜APAC AIA」。

完成標準：瀏覽器分頁不再空白；Lighthouse 的 Document title 通過。

P1 · 頁面語言

將目前這個中文首頁標示為繁體中文

頁面最外層的 <html> 目前是 lang="en-US"，但首頁主要可見內容是繁體中文。這一頁應標示 lang="zh-TW"，完整英文段落再個別標示 lang="en"。

完成標準：頁面最外層的 <html> 顯示 lang="zh-TW"；完整英文段落顯示 lang="en"。

P1 · 文字對比

加深桌面導覽的兩個連結

「論壇活動 Event」與「聯繫 Contact」量測為 4.16:1；目前 17px 一般字重需達 4.5:1。把文字顏色稍微加深即可，不必改黃色導覽背景。

完成標準：一般狀態、hover 與 focus 狀態的文字對比都至少 4.5:1。

P1 · 裝飾圖片

三個藍色圖案統一使用空的 alt

「多元共融／以人為本／科技創新」上方的三個藍色圖案只是裝飾。Live DOM 顯示「多元共融」已是 alt=""；另外兩個仍有英文替代文字，會在文字標籤之前多出重複描述。

WordPress：將「以人為本」與「科技創新」圖片的 Alt Text 清空。「多元共融」維持目前設定。

staging 複查：儲存後確認三個圖案都輸出 alt=""，再檢查 accessibility tree 不再列出它們。

完成標準：三個圖案都是 alt=""；下方中英文文字仍正常顯示。

CSS 問題的畫面與原因

寬度目前結果建議版面
320px圖文已上下排列，但內文左右留白疊加，文字只剩窄直條。單欄；圖片在前、文字在後；正文保留約 24px 左右安全留白。

1280px 以上第一、三組接近等高；第二組仍差約 42px。保留兩欄；圖片以 cover 填滿同列高度。

本次上線使用的 CSS：先在 staging 驗證

這項 CSS 應納入本次上線。若時間允許，先在 staging 完整驗證，再與本次內容一起套到正式站。若為了活動宣傳與購票入口必須先行上線，可先公開內容，但需保留 staging，並將 CSS 驗證與正式站修正列為上線後立即完成的後續工作。

目前預檢結果：已將上述 class 與 CSS 暫時注入目前的 live DOM，只在本機瀏覽器量測，沒有修改網站。320／768／1024／1280／1440／1742／1920px 均沒有水平捲軸；320／768px 為單欄圖片在前，1024px 以上為兩欄，桌面圖片與文字卡已等高。

仍需在 staging 完成最終驗收：只有實際儲存到 WordPress 後，才能確認 class 加在正確區塊、CSS 載入順序與快取沒有造成差異，並查看三張圖在 768／1024／1440px 的人物主體與裁切效果。確認後再將同一份 CSS 套到正式站。

P1｜上線後第一輪與內容維護

上線後第一輪 · Heading

保留視覺樣式，只修正 heading tag

目前 H1 後直接出現 H4；六個年份、三張「我們創造什麼連結」卡和四個議題使用 H5。「三大價值」區段內三張完整卡片的名稱只是粗體文字，不是標題。螢幕閱讀器用標題清單瀏覽時，會看到不連續且不完整的頁面大綱。頁首插圖下方重複出現的三個價值摘要沒有各自帶領內文，應維持一般文字。

這不是字級或視覺樣式問題，而是整頁的導覽骨架沒有正確反映畫面上的內容關係。只看畫面時，仍可利用位置、卡片背景和字體大小判斷章節；螢幕閱讀器使用者則常透過標題清單或逐個標題跳轉，快速找到想看的區段。

  • H2 後直接出現 H5，會讓年份與卡片看起來像位於不存在的 H3、H4 章節之下。
  • hero 介紹句被標成 H4，會在標題清單裡被誤認為某個深層子章節。
  • 「三大價值」區段內的三張完整卡片各有獨立說明，但卡片名稱不是 heading；頁首的三個短摘要則不是內容標題，不需加入 heading。

單純從 H2 跳到 H5 並不必然等於 WCAG 違規；此處需要修正的原因，是目前的 heading 標記沒有忠實表達畫面已呈現的結構與關係，涉及 WCAG 1.3.1 資訊及關係與 WCAG 2.4.6 標題與標籤。

修正方式：在 WordPress 將對應區塊改成正確的 HTML heading level，並以 CSS 維持原有字級、粗細、顏色與間距。

完成標準：全頁只保留一個 H1；每個主要區段各使用一個 H2；各區段內有獨立說明內容的卡片名稱與年份可使用多個 H3；hero 標語改成一般段落；頁首三個價值摘要維持一般文字。修正後重新進行 Heading 導覽與螢幕閱讀器測試；修正前不能把標題導覽判定為通過。
